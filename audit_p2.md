# Phase 2 — code versus paper

## Scope and decision rule

This audit uses the authoritative draft `ToRS_paper/CAFE_ToRS_EceErdem (2).pdf`, the supplied supplementary PDF, and the current repository. PDF locations below use the physical PDF page followed, where useful, by the article page (`111:x`). I did not run any experiment. A code path merely existing is not evidence that a stored result was produced by it; execution provenance remains a Phase-1 question.

Verdicts are used literally:

- **MATCH** — the cited code implements the cited paper statement.
- **MISMATCH** — the code and statement differ, or the paper claims a protocol for which the identifiable code path does something else.
- **CANNOT VERIFY FROM AVAILABLE FILES** — the statement is absent, internally under-specified, delegated to an unavailable dependency, or is a historical claim not recoverable from the files.

## Bottom line

- **MATCH** — The corrected structural-EG graph construction now implements the paper's simple-undirected set unions, zero-centrality filtering, Gini expression, and percentage EG definition (`metrics/graph_utils.py:41-94`, `metrics/graph_utils.py:134-151`, `metrics/equality_gain.py:31-59`, `metrics/equality_gain.py:99-144`).
- **MISMATCH** — The paper presents generalized closeness exactly, but the headline implementation switches above `5,000` nodes to sampled outbound approximate closeness with default `epsilon=0.1` and seed `42`; this affects Pokec-n and Brightkite under the paper's own node counts (draft Table 13, PDF p.32; `metrics/centrality_equality_gain.py:311-328`, `metrics/centrality_equality_gain.py:344-410`, `experiments/run_cafe.py:317-320`).
- **MISMATCH** — The paper says the four non-Brightkite datasets are randomly split. The splitter protects a spanning forest in training and randomizes only non-tree edges (`backbone/snap_dataset.py:258-304`). Brightkite likewise protects tree edges and applies chronology only to the remaining edges (`data/SNAP/brightkite/create_temporal_split_brightkite.py:157-210`). These are constrained splits, not the stated protocol.
- **MATCH** — The new corrected-EG campaign uses one fixed split and distinct training seeds: the aggregate job launches one task per seed and `run_significance.py` reseeds every learned arm (`jobs/egfix/aggregate.job:97-119`, `experiments/run_significance.py:382-400`, `experiments/run_significance.py:436-440`, `experiments/run_significance.py:466-492`).
- **MISMATCH** — The legacy table jobs still call `run_cafe.py` for `--runs 10` without `--reset_seed_per_model`; the flag defaults false, while the dataset loader resets Torch and NumPy during every random split. Thus nominal repetitions in that path do not implement the draft's “vary training seed” statement (`experiments/jobs/t04_cafe.job:118-130`, `experiments/run_cafe.py:138-144`, `experiments/run_cafe.py:375-381`, `backbone/snap_dataset.py:240-245`).
- **MISMATCH** — Eq. (8) is not evaluated edgewise. The configured MLP returns `pos_out` with shape `[B,1]`, while `core_weight` has shape `[B]`; their multiplication broadcasts to `[B,B]`, so code averages all score-weight cross-pairs instead of the paper's matched-edge products (`backbone/layer.py:147-168`, `backbone/model.py:699-706`, `fairness_methods/inprocessing.py:480-496`, `fairness_methods/inprocessing.py:660-681`). Independently, the positive-edge term is mean-reduced while the selected AUC base loss is sum-reduced; the repository itself calls that default penalty numerically inert (`fairness_methods/inprocessing.py:24-47`, `backbone/loss.py:4-7`, `experiments/egfix_protocol.py:72`).
- **MISMATCH** — Appendix B declares each F1/F2/F3 family to contain both CAFE variants (`40` contrasts), while the analysis groups Holm correction by the full comparison string, producing a separate family for “CAFE-In vs ...” and “CAFE-Pre vs ...” (`analysis/significance_tests.py:106-111`, `analysis/significance_tests.py:128-173`). The correction denominator is therefore narrower than declared.
- **MISMATCH** — The draft defines signed `Delta SP`, but the code returns its absolute value. Later draft tables call the quantity absolute, so the paper is internally inconsistent as well (`metrics/demographics.py:224-256`; draft Section 3.3, PDF p.7 versus Tables 9 and 17, PDF pp.25 and 37).
- **MATCH** — The corrected selector enforces validation-only objectives, the stated grids, Pareto filtering, front normalization, and the weighted Chebyshev ASF (`experiments/egfix_protocol.py:31-84`, `jobs/egfix/selection.job:106-137`, `analysis/egfix_finalize_selection.py:329-437`).
- **CANNOT VERIFY FROM AVAILABLE FILES** — The draft's claim that ASF weights were fixed before results were inspected is historical. No timestamped preregistration or immutable pre-result record establishes it; the code only records the present constants (`experiments/egfix_protocol.py:78-84`).
